% --- Slide: Характеристика проблемных вопросов практики (v6.3 — стиль Гаврилова) -
\begin{frame}{Проблемы практики обогащения товарных каталогов}
\fontsize{10.5pt}{13pt}\selectfont
\begin{itemize}
    \setlength{\itemsep}{0.5em}
    \item Каталоги интернет-магазинов --- \textbf{десятки миллионов} карточек;
          качество атрибутов определяет поиск, фильтры и рекомендации.

    \item PIM-системы \textbf{хранят} атрибуты, но не извлекают их из текста;
          партнёры присылают лишь базовые поля (название, бренд, состав) ---
          \textbf{50--90\,\%} целевых атрибутов приходят пустыми.

    \item \textbf{Ручное} заполнение не масштабируется на $10^7$ карточек
          $\times$ десятки атрибутов --- новые товары выходят с задержкой.

    \item \textbf{Прямой вызов} большой языковой модели (БЯМ, англ.~LLM) на каждую
          ячейку возможен технически, но экономически неприемлем.
\end{itemize}
\end{frame}

% --- Slide: Цель, задачи, объект, предмет (v6.0 формальная рубрика) -
\begin{frame}{Цель, задачи, объект, предмет}
\fontsize{9.5pt}{11.5pt}\selectfont
\textbf{Цель.} Разработать программное средство автоматизированного
обогащения карточек товаров на основе гибридной каскадной архитектуры
с поатрибутной маршрутизацией, обеспечивающее заданную точность
при кратно меньшей стоимости, чем прямой вызов большой языковой модели.

\vspace{0.15em}
\textbf{Задачи}
\begin{enumerate}
    \setlength{\itemsep}{0em}
    \item Спроектировать каскад с поатрибутной политикой.
    \item Реализовать слои как независимо обновляемые компоненты.
    \item Подготовить эталон и контроль без пересечения кодов.
    \item Оценить точность и стоимость; сравнить с прямой БЯМ.
    \item Реализовать программный комплекс (REST + Web-UI).
\end{enumerate}

\vspace{0.15em}
\textbf{Объект.} Процессы обогащения карточек товаров атрибутными значениями
из неструктурированных партнёрских полей.\\
\textbf{Предмет.} Методы и алгоритмы автоматического заполнения атрибутов
гибридными каскадными системами с поатрибутной маршрутизацией.
\end{frame}

\begin{frame}{Научная и практическая значимость}
\fontsize{10pt}{12.5pt}\selectfont
\textbf{Научная значимость.}
\begin{itemize}
    \setlength{\itemsep}{0.2em}
    \item \textbf{Гетерогенный каскад} (правила, машинное обучение, большая

          вызовом БЯМ.
    \item \textbf{Методика} поатрибутной маршрутизации по \textbf{калиброванной
          уверенности}: каждый атрибут передаётся на следующий слой по своему
          порогу.
\end{itemize}

\vspace{0.5em}
\textbf{Практическая значимость.}
\begin{itemize}
    \setlength{\itemsep}{0.2em}
    \item Кратное сокращение стоимости обработки и ручной нагрузки
          контент-менеджеров при автоматическом заполнении атрибутов каталога.
\end{itemize}
\end{frame}

\begin{frame}{Состав требований к программному средству}
\fontsize{8.5pt}{10.5pt}\selectfont
\begin{columns}[T]
\column{0.48\textwidth}
\textbf{Функциональные (ФР)}
\begin{itemize}
    \setlength{\itemsep}{0.1em}
    \item \textbf{F1.} Возврат значения целевого атрибута либо явный отказ.
    \item \textbf{F2.} Слой-источник предсказания.
    \item \textbf{F3.} Калиброванная уверенность $c\in[0,1]$.
    \item \textbf{F4.} Эскалация на запасной слой.
    \item \textbf{F5.} Байес-валидация подозрительных предсказаний.
    \item \textbf{F6.} Поатрибутная настройка через конфиг.
\end{itemize}

\column{0.48\textwidth}
\textbf{Нефункциональные (НФР)}
\begin{itemize}
    \setlength{\itemsep}{0.1em}
    \item \textbf{N1.} Точность $\ge 85\,\%$ (каскад) / $\ge 90\,\%$ ($+$ БЯМ).
    \item \textbf{N2.} Стоимость снижена в $\ge 2{,}5\times$ раз vs прямой БЯМ.
    \item \textbf{N3.} Время отклика $\le 500$\,мс (каскад) / $\le 5$\,с (БЯМ).
    \item \textbf{N4.} Многоязычность ($\ge 5$ языков).
    \item \textbf{N5.} Локальное развёртывание (без внешних API).
\end{itemize}
\end{columns}
\end{frame}

\begin{frame}{Слой 2: выбор алгоритма классификации}

это нужно для корректных поатрибутных порогов. Сам классификатор сменяется
через конфигурацию.
