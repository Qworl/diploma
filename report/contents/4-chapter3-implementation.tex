Глава описывает программную реализацию системы: 3.1 — каскад и демонстрационный комплекс; 3.2 — данные и предобработку; 3.3 — численные результаты и сценарии проверки.

\subsection{Описание программного обеспечения}

\subsubsection{Программная реализация слоёв каскада}

Архитектурная роль слоёв описана в 2.2.1, поток управления и формула вывода $\hat{y}_k$ — в 2.1; ниже приведены только детали реализации. Алгоритм обработки одного запроса в нотации ГОСТ 19.701-90 показан на рисунке 3.1; на каждом слое принимается одно из двух решений (закрыть атрибут или передать дальше), слои упорядочены по росту стоимости. Вход — партнёр-доступные поля; слой 2 обучается только на них, что исключает утечку через теги OFF.

  \caption{Блок-схема алгоритма обработки запроса (нотация ГОСТ 19.701-90)}

\textbf{Слой 0 — категорайзер.} LightGBM поверх TF-IDF-представления (term frequency × inverse document frequency, частотно-инверсный показатель) (n-граммы 1–2) с порогом OOD (out of distribution, выход за пределы обучающего распределения). Артефакты: \texttt{models/category\_router\_v3\_\{lgbm,vec\}.pkl}, \texttt{\_threshold.json}. При ошибке в категории атрибуты товара получают неверную схему и засчитываются как неверные предсказания.

\textbf{Слой 1 — экстрактор регулярных выражений.} Реализация — \texttt{src/pipeline/regex/extractor.py}. Разбирает product\_name и quantity; распознаёт формы пасты, процент какао, маркер цельнозернового состава, источник молока в сырах (chèvre / brebis / bufala), маркеры PDO/AOP/DOP, маркеры ультра-обработанного сыра. Покрытие неровное по категориям: около 18~\% на pasta, 23~\% на chocolate и 3~\% на cheeses; точность на закрытых ячейках — 87,0--100~\% (см.~3.3.3.2).

\textbf{Слой 2 — классификатор машинного обучения.} Основной рабочий слой (73,2 \% всех решений системы). Вход — конкатенация \texttt{product\_name + brands + ingredients\_text + quantity}. SBERT-кодировщик \texttt{paraphrase-multilingual-mpnet-base-v2} (768d, 50+ языков) конкатенируется с TF-IDF (n-граммы 1–2, top-5000), сжатым TruncatedSVD до 128 компонент; итого 896-мерное гибридное пространство. Для каждой пары (категория, атрибут) обучен XGBoost-классификатор \texttt{\{cat\}\_v4\_mpnet\_tfidf\_noleak\_\{attr\}\_xgb.pkl} с регуляризацией (subsample=0.8, colsample=0.8, ранняя остановка), Platt-калибровкой и порогом уверенности, подобранным на валидационном срезе по macro-F1 × coverage. Точность на покрытом срезе — 94,9–98,6 \% (см.~\ref{subsec:layer_accuracy}).

\textbf{Слой 3 — байесовский валидатор.} Сеть в \texttt{models/\{cat\}\_stratified\_bayesian.pkl}; структура — Hill Climb + BIC. По итогам 3.3.4 используется как валидатор плотностей: для предсказания слоя 2 вычисляется \texttt{P(value | evidence)}, при попадании в нижний 5-перцентиль ячейка помечается флагом.

\textbf{Слой 4 — запасной слой на большой языковой модели.} Реализация — \texttt{src/pipeline/llm\_fallback/enrich.py}. В 3.3.2 оцениваются пять моделей: Claude Sonnet 4.5, GPT-4o, Gemini 2.5 Flash, открытая gpt-oss-120b и открытая малая llama-3.2-3b\footnote{Состав моделей зафиксирован на момент проведения экспериментов (первое полугодие 2026~года). Архитектура каскада не привязана к конкретному поставщику, и при появлении новых поколений моделей Слой 4 заменяется без переобучения остальных слоёв; переоценка на актуальных моделях вынесена в перспективы развития темы (Заключение).}. Промпт содержит схему атрибутов категории, требуемый JSON-формат и партнёр-доступные поля.

\subsubsection{Демонстрационный комплекс и контракт API}

Демонстрация имитирует встраивание в бизнес-процесс интернет-магазина и состоит из трёх компонентов: Go-шлюза API (\texttt{demo/gateway/}, $\approx$200 строк на стандартной \texttt{net/http} — валидация JSON, проксирование, CORS, отдача статики), Python/FastAPI ML-сервиса (\texttt{demo/ml\_service/} — при старте подгружает SBERT-кодировщик, 20 XGBoost-классификаторов, байесовские сети и слой 0; после прогрева $\approx$15–20 с слои 0–3 отвечают за десятки миллисекунд), одностраничного HTML/JS-фронтенда. Эндпоинты: \texttt{POST /api/enrich}, \texttt{GET /api/categories}, \texttt{GET /health}, \texttt{POST /api/explain}.

Запрос \texttt{POST /api/enrich} принимает JSON с полями \texttt{category} (опционально), \texttt{product\_name}, \texttt{brands}, \texttt{ingredients\_text}, \texttt{quantity}; ответ содержит \texttt{category}, агрегированные счётчики и объект \texttt{predictions} с указанием слоя-источника (regex / ml / llm\_fallback), уверенности и результата валидации для каждого атрибута. Пример пары запрос–ответ:

\begin{verbatim}
// запрос
{ "category": "pasta", "product_name": "Spaghetti #5 Barilla",
  "brands": "Barilla", "ingredients_text": "Durum wheat semolina", "quantity": "500g" }
// ответ
{ "category": "pasta", "n_attrs_total": 8, "n_covered": 7, "n_llm_fallback": 1,
  "predictions": {
    "pasta_shape": { "value": "spaghetti", "layer": "regex", "confidence": 1.00 },
    "grain_type":  { "value": "wheat", "layer": "ml", "confidence": 0.99 },
    "is_filled":   { "value": null, "layer": "llm_fallback", "confidence": 0.0 } } }
\end{verbatim}

Явная отметка слоя-источника компенсирует ограниченную интерпретируемость слоёв 2/3 на уровне отдельного товара. Запуск — одной командой \texttt{bash reproduce.sh demo}; готовность проверяется через \texttt{GET /health}. Стек технологий обоснован в 2.2.8 (таблица 2.1).

\subsection{Данные}

\subsubsection{Источник данных, фильтрация и стратифицированная выборка}

Основой выбран открытый каталог Open Food Facts (далее — OFF) \cite{ref_13} — краудсорсинговая база $\approx$4,5~млн позиций под лицензией ODbL v1.0, допускающей коммерческое использование при условии share-alike. Производные выборки и эталоны размещены в репозитории под совместимой лицензией с указанием авторства. Дамп (526 МБ) получен командой \texttt{python -m src.data.download --source off}. Выбор обусловлен открытостью лицензии (воспроизводимость), мультиязычностью (50+ языков) и наличием структурированных нутриентных показателей и регуляторных тегов, на которых построен эталон (3.2.3). Область охвата — три категории (pasta, chocolate, cheeses), отобранные по критериям 1.3.

Поля OFF разделены на партнёр-доступные (\texttt{product\_name}, \texttt{brands}, \texttt{quantity}, \texttt{ingredients\_text}, \texttt{code}) и целевые выходные (\texttt{categories\_tags}, \texttt{labels\_tags}, \texttt{*\_100g}, \texttt{ingredients\_analysis\_tags}); целевые поля не передаются на вход обучаемых компонентов под угрозой утечки. Фильтрация по категории (\texttt{src/data/filter.py}) использует списки включения/исключения \texttt{categories\_tags} (для pasta включение — \texttt{en:pastas}, исключение — \texttt{en:potato-products}, \texttt{en:noodles}). После фильтрации применяется стратифицированная по языку выборка (langdetect, страты FR/EN/DE/IT/ES) объёмом $\approx$250 товаров на страту, итого $\approx$1250 на категорию (таблица 3.2.1).

\subsubsection{Эталонная разметка: иерархическая схема трёх ярусов}

Эталон построен как процедура из трёх ярусов с качественно разным классом свидетельств на каждом ярусе. \textbf{Ярус 0 (нутриент-производные)} — детерминированное бакетирование числовых полей: \texttt{pasta/protein\_class} из \texttt{proteins\_100g} по регламенту ЕК 1924/2006, точность 100~\% при достоверных нутриентах. \textbf{Ярус 1 (тег-производные)} — эталон из регуляторных тегов: \texttt{is\_organic} из \texttt{en:organic}, \texttt{is\_gluten\_free} из \texttt{en:gluten-free}, \texttt{is\_pdo} из \texttt{en:protected-designation-of-origin} (правовая защита в ЕС, регламенты 834/2007 и 1151/2012). \textbf{Ярус 2 (семантически-текстовые)} — признаки без детерминированного правила (pasta\_shape, chocolate\_type, milk\_source, texture и т.~д.): эталон — согласие трёх независимых LLM (Claude Sonnet 4.5, GPT-4o, Gemini 2.5 Flash) на полной выборке 1250~$\times$~3 категории при правиле «не менее двух из трёх» (согласованность 97,7~\%); несогласованные позиции переразмечены слепо Claude Opus 4 на 688 ячейках (human gold) — это нижняя консервативная оценка точности.

\subsubsection{Разбиение без пересечения товарных кодов (code-disjoint)}

Случайное разбиение не подходит: одна и та же товарная позиция в обучении и тесте даёт прямую утечку. Применяемое разбиение — \textbf{code-disjoint} по идентификатору товара (\texttt{src/eval/build\_noleak\_artifacts.py}): из расширенного серебра удаляются все коды, попавшие в любой из gold-источников. Основной эталон — LLM-consensus gold объёмом 16\,360 cascade-valid ячеек по 20 атрибутам (\texttt{headline\_v4\_mpnet\_tfidf\_noleak.parquet}); консервативная нижняя оценка — human gold Claude Opus 4 объёмом 566 cascade-valid ячеек. Тестовая выборка содержит 186 / 301 / 297 уникальных товарных кодов в pasta / chocolate / cheeses.

\textbf{Brand overlap.} 82,5~\%, 84,9~\% и 82,7~\% брендов в тестовой выборке pasta / chocolate / cheeses встречаются и в обучающем пуле. Полноценное brand-disjoint разбиение не заявляется: концентрация брендов в OFF (Lindt, Barilla, Président встречаются в десятках позиций каждый) делает построение brand-disjoint эталона той же мощности невозможным без переразметки. Brand-disjoint подмножество доступно как точечная проверка устойчивости (3.3.7.3): 17 / 19 / 28 кодов на pasta / chocolate / cheeses, чьи бренды отсутствуют в обучающем пуле.

\subsubsection{Дополнительные источники сигналов}

Производственная конфигурация слоя 2 опирается строго на партнёр-доступные текстовые поля; режим вывода совпадает с режимом обучения. Дополнительные источники (фотографии этикеток через OCR EasyOCR и CLIP-эмбеддинги ViT-B/32 \cite{ref_43}; внешний справочник USDA Branded Foods \cite{ref_44}) проверены экспериментально, но в производственную конфигурацию не включены: мультимодальный сигнал не дал прироста выше шума и потребовал бы доступа к OFF image dump в режиме вывода, USDA используется только для сверки эталона яруса 0. Правило «вход = партнёр-доступные поля» соблюдено во всех оценках 3.3.

\subsection{Доказательство работоспособности и применимости}

\subsubsection{Условия проверки и метрики}

Эксперименты проведены на двух согласованных эталонных срезах. Основной --- LLM-consensus gold (\texttt{consensus\_gold\_v4.parquet}) объёмом 16\,360 ячеек cascade-valid (17\,062 в-scope) по 20 атрибутам; служит источником главного показателя. Консервативная нижняя оценка --- human gold Claude Opus 4 объёмом 566 ячеек cascade-valid (688 в-scope) по тем же 20 атрибутам. Знаменатель cascade-valid --- ячейки, на которых каскад вернул конкретный класс (Слой 1 rule\_h $\cup$ Слой 2 ML $\cup$ Слой 3 rule\_l); 702 / 122 ячейки запасного слоя LLM не входят в cascade-only знаменатель, так как в производственном режиме на них каскад отказывается и эскалирует в LLM. Использованы модели с суффиксом \texttt{\_mpnet\_tfidf\_noleak} (MPNet + TF-IDF + XGBoost, переобучение без утечки), разбиение train/val/test без пересечения товарных кодов в пропорции 60/20/20. Согласованность трёх LLM-разметчиков (Claude Sonnet 4.5, GPT-4o, Gemini 2.5 Flash) --- 97,7 \% при правиле «не менее двух из трёх совпадают», спорные позиции переразмечены Claude Opus 4 слепо; согласованность LLM-consensus и human gold на пересечении --- 92 \%, $\kappa$ Коэна > 0,80.

Метрики ($\text{acc}^{\text{cov}}_k$, $\text{cov}_k$, $\text{acc}^{\text{e2e}}_k$, стоимость) определены в 2.1.4. Доверительные интервалы --- кластерный бутстрэп по брендам (1000 итераций, перцентили 2,5~/ 97,5~\%, \texttt{src/diagnostics/ml/bootstrap\_ci\_brand\_clustered.py}); такой интервал учитывает внутрибрендовую корреляцию и на ряде атрибутов на 15--30~\% шире наивного интервала Вильсона. Для опорной E2E-оценки дополнительно рассчитан кластерный бутстрэп по товарным кодам (B=1000, 2\,812 уникальных кодов): интервал [92,3; 93,6]~\% против Вильсона [92,6; 93,4]~\% при оценке 93,0~\% (расширение 64~\%)\footnote{Воспроизводится \texttt{src/eval/bootstrap\_ci\_grouped.py}; артефакт --- \texttt{datasets/processed/e2e\_bootstrap\_ci.json}; ячейка \texttt{bootstrap-grouped-ci} в \texttt{notebooks/03\_evaluate.ipynb}.}; расхождение умеренное, опорное значение 93,0~\% устойчиво.

\subsubsection{Воспроизводимость}
\label{sec:reproducibility}

Численные результаты 3.3 пересоздаются из артефактов через \texttt{reproduce.sh} ($\approx$час на ноутбуке): перезапуск \texttt{notebooks/03\_evaluate.ipynb} и \texttt{notebooks/05\_method\_comparison.ipynb} над \texttt{v4\_e2e\_router\_eval.json}, \texttt{v4\_metric\_table\_v2.json}, \texttt{cascade\_preds\_\{cat\}\_gold.parquet}, \texttt{method\_comparison\_results.parquet} пересоздаёт TeX-фрагменты и PNG локально. Артефакты VM-уровня (исходные прогоны LLM-разметчиков и переобучение Слоя 2 без утечки) обновляются отдельно, их пересборка вынесена в перспективы развития; качественные выводы 3.3 от этого не зависят. Числа 3.3.2 получены post-hoc после устранения утечки бренда; единственная заранее объявленная гипотеза --- H1 для обучаемого маршрутизатора (3.3.5).

\subsubsection{Главный результат: точность и стоимость производственной конфигурации}
\label{subsec:headline_result}

Каскад сопоставлен с пятью одиночными вызовами LLM на едином тестовом срезе без пересечения товарных кодов: 16\,360 cascade-valid ячеек LLM-consensus gold и 566 cascade-valid ячеек human gold по 20 атрибутам (для pasta/protein\_class срез сокращён до 24 ячеек). Заголовочные метрики получены на гибридном 896-мерном представлении (MPNet 768d $\oplus$ TF-IDF SVD 128d); в роли Слоя 4 и опорной «одна LLM на всё» --- пять моделей: Claude Sonnet 4.5, GPT-4o, Gemini 2.5 Flash (закрытые), gpt-oss-120b и llama-3.2-3b (открытые). Источники: \texttt{headline\_v4\_mpnet\_tfidf\_noleak.parquet}, \texttt{grand\_acc\_summary\_v4.parquet}. Слои 1--3 закрывают 95,9~\% ячеек без обращения к LLM; оставшиеся 4,1~\% --- запасной слой. Стоимость нормирована к «все ячейки --- Sonnet 4.5», соотношение вход/выход $\approx$500 / 200 токенов.

\textbf{Разграничение понятий.} \emph{Покрытие каскада} = $1 - \text{fallback rate} = 95{,}9\,\%$ (Слои 1--3 выдали уверенный ответ); \emph{покрытие производственной цепочки} (E2E coverage) = $97{,}3\,\%$ (с учётом ошибок маршрутизатора Слоя 0 и удачных ответов Слоя 4 при том же знаменателе); \emph{архитектурное снижение стоимости} = $95{,}9\,\%$ ($\approx 24\times$) — это то же число, что и покрытие каскада, по построению ($1 - \text{fallback rate}$). Связь: $\text{E2E coverage} = (1 - \text{router loss}) \times (\text{cascade-only coverage} + \text{LLM success rate} \times \text{fallback rate})$.

\subsubsection{Обобщение на новые бренды (brand-disjoint side-study)}
\label{sec:brand_disjoint_side_study}

В §3.2.4 зафиксировано, что разбиение train/test в основной оценке выполнено по идентификатору товара (code-disjoint), а бренды пересекаются между обучающим пулом и тестовой выборкой на 82--85~\% по категориям. Чтобы выяснить, насколько результат каскада зависит от знакомых брендов, проведено отдельное контрольное исследование с обучением и оценкой на brand-disjoint срезе. Цель --- получить независимую нижнюю оценку обобщающей способности слоя машинного обучения, когда появляются товары неизвестных брендов.

\textbf{Методология.} Источник плотно размеченных данных --- \texttt{\{cat\}\_stratified\_silver\_extended.parquet} ($\approx$1\,250 кодов на категорию). Для каждой из трёх категорий (паста, шоколад, сыры) построены два разбиения с одинаковой долей тестовой части ($\approx$20~\%) и одним случайным зерном (\texttt{seed=42}): (a) обычное случайное по кодам и (b) brand-disjoint с замыканием по бренд-токенам --- любой код, содержащий хотя бы один бренд из тестовой выборки, переносится в тест целиком, пока множества не станут полностью непересекающимися. Brand overlap по итогу: для code-disjoint --- 56--68~\% брендов теста встречаются и в обучении (как и в основном эксперименте); для brand-disjoint --- ровно 0~\%. На каждом разбиении переобучены классификаторы XGBoost второго слоя (мультиязычные векторные представления MiniLM-L12 + sigmoid-калибровка, та же гиперпараметризация, что и в основной конфигурации). Воспроизводится: \texttt{src/eval/build\_brand\_disjoint\_split.py} строит разбиения, \texttt{src/eval/train\_brand\_disjoint.py} запускается на ВМ (правило проекта запрещает обучение локально), \texttt{src/eval/eval\_brand\_disjoint.py} проводит сравнение. Тикет --- \texttt{docs/po/tickets/2026-05-28-brand-disjoint-side-study.md}, артефакт --- \texttt{datasets/processed/v4\_brand\_disjoint\_eval.json}.

\textbf{Результат.} На общем срезе из 4\,538 ячеек code-disjoint и 5\,436 ячеек brand-disjoint точность только-ML слоя составила 83,03~\% и 82,56~\% соответственно; разность $-0{,}47$~п.\,п. при разнице макро-F1 $-0{,}017$. Таблица~\ref{tab:brand_disjoint_compare} приводит покатегорийную и глобальную разбивку.

\input{contents/tables/brand_disjoint_compare}

\textbf{Интерпретация.} Деградация меньше 1~п.\,п. укладывается в пределы дисперсии при выборках $\sim$1\,000 ячеек на категорию. Это значит, что слой машинного обучения каскада опирается на структуру наименования и нутри-сигналы товара, а не на запоминание брендов. На двух из трёх категорий (шоколад $-1{,}27$~п.\,п., сыры $-0{,}67$~п.\,п.) виден незначительный спад, на пасте --- даже небольшой прирост $+0{,}45$~п.\,п. (то, что знак прыгает, говорит, что эффект в диапазоне случайной флуктуации). То есть заголовочные показатели cascade-only 95,5~\% и E2E 93,0~\% переносятся на товары неизвестных брендов с потерей не больше $\approx$0,5~п.\,п., и разбиение по товарным кодам в основной оценке не создаёт оптимистичного смещения за счёт утечки бренда.

Контрольное исследование ограничено: тестовый срез контрольной оценки в 2--3 раза меньше основной (5,4~тыс. ячеек против 16,4~тыс.), считаются метрики только слоя 2 (без вклада регулярных правил и Bayes-валидатора), сравнение проводится на плотно размеченной подвыборке silver\_extended, а не на полном LLM-consensus gold. Полноценная оценка end-to-end в brand-disjoint режиме потребовала бы переразметки эталона той же мощности, что выходит за рамки текущей работы.

\label{subsec:calibration}

Среднее ECE сырого XGBoost — 0,070 (по 20 замерам); у большинства атрибутов не превосходит 0,08. Ухудшение --- у четырёх атрибутов с изначально низкой ECE: cheeses/country\_of\_origin (0,015 → 0,064), cheeses/is\_ultra\_processed (0,025 → 0,056), pasta/pasta\_shape (0,046 → 0,060), chocolate/is\_filled (0,055 → 0,058); тут главную роль играют выборочные колебания. \subsubsection{Таксономия ошибок каскада}
\label{sec:failure-taxonomy}

Раздел отвечает на вопрос «где и почему ошибается каскад» --- честная диагностика, важная для защиты: она отделяет собственные дефекты производственной цепочки от шума эталонной разметки. Анализ проведён на 846 несовпадающих ячейках (cascade\_pred $\neq$ gold) из 16\,360 cascade-valid LLM-consensus gold по трём категориям (\textit{pasta}, \textit{chocolate}, \textit{cheeses}); это операционная частота ошибок 5,2~\%, соответствующая cascade-only точности 94,8~\% на этом пуле\footnote{Здесь и далее в \S3.3 «Таксономия ошибок каскада» эталон --- моментальный снимок \texttt{cascade\_errors\_taxonomy\_v4.parquet}, на котором cascade-only точность составила 94,8~\% (846 ошибок / 16\,360 ячеек). Заголовочное число ВКР по этой же выборке после финализации расширенного перезапуска консенсуса (\texttt{v4\_e2e\_router\_eval.json}, 2026-05-27) составляет 95,5~\% --- разница обусловлена пересчётом нескольких пограничных классов между моментальными снимками; качественные выводы таксономии (декомпозиция ошибок по 4 классам, оценка silver-noise) не зависят от этого сдвига в пределах 0,7~п.\,п.}. Ячейки, на которых каскад отказался от ответа (запасной слой LLM, 4,1~\%), не входят в знаменатель и анализируются отдельно в §3.3.5.

Каждая ошибка отнесена к одному из шести изначально допустимых классов с приоритизированной классификацией (первый совпавший выигрывает): (1) \textit{ложное срабатывание Слоя 1} --- низкоуровневый или высокоуровневый regex-шаблон сработал на синтаксически подходящем, но семантически неверном тексте (например, \texttt{Three Cheese Ravioli} закрыт правилом is\_filled=false по антипаттерну); (2) \textit{промах запасного слоя} --- запасной слой на большой языковой модели (Слой 4) вернул значение, отличное от эталона (по определению cascade-only знаменателя пустой класс, поскольку cascade\_pred у ячеек запасного слоя равен \texttt{None}); (3) \textit{гиперпредсказание на null-эталоне} --- gold отсутствует, prediction вернул конкретный класс (по построению пуст: фильтр \texttt{in\_scope=True} требует ненулевого gold); (4) \textit{шум разметки (silver-noise)} --- ячейки, где консенсус трёх LLM-разметчиков не достигает порога $\geqslant 2/3$ или отмечены как \texttt{disputed} в \texttt{manual\_gold\_consensus.parquet}; (5) \textit{спутывание близких классов} --- пара (gold, prediction) принадлежит заранее определённому per-attribute mapping <<семантически смежных>> значений (semi\_soft$\leftrightarrow$soft, dark$\leftrightarrow$milk, with\_nuts$\leftrightarrow$with\_fruit, italy$\leftrightarrow$france и т.\,п.); (6) \textit{ML-смещение в дальний класс} --- всё прочее, когда XGBoost выбрал семантически удалённый класс.

Применение классификатора оставило четыре непустых класса (таблица~\ref{tbl:failure-taxonomy}). Классы~2 и~3 пусты по построению знаменателя: cascade-only ошибки определены на ячейках, где cascade\_pred ненулевой и in\_scope=True; это методологическое уточнение, а не отсутствие явления --- промахи запасного слоя и null-эталоны анализируются отдельно в §3.3.5 и §3.3.4 соответственно.

\subsubsection{Чувствительность к выбору порога отсечки}
\label{sec:threshold_sensitivity}

Поатрибутные пороги уверенности $\tau_a$ подобраны процедурой \texttt{find\_best\_threshold} (оптимизация macro-F1$\,\times\,$coverage на отдельном валидационном срезе, \S\,\ref{subsec:schema_refinement}). Чтобы убедиться, что выбранная точка устойчива по совокупному критерию «точность $\leftrightarrow$ стоимость», проведён post-hoc анализ чувствительности: пороги синхронно сдвигаются на $\Delta\in\{-0{,}10;\,-0{,}05;\,0;\,+0{,}05;\,+0{,}10\}$ без переобучения моделей. \subsubsection{Стоимостно-чувствительный маршрутизатор: отрицательный результат на проверке гипотезы H1}

В подразделе зафиксирован результат заранее объявленной проверки гипотезы H1 о превосходстве обучаемого маршрутизатора над статическим правилом.

\paragraph*{Идея, гипотеза H1 и процедура оценки.}
Финальный механизм направления ячеек в LLM --- статическое per-(категория, атрибут) правило. Рассматривалась обучаемая альтернатива: XGBoost-маршрутизатор предсказывает надёжность ответа каскада, при вероятности ниже~$\tau$ ячейка идёт в LLM. \textbf{H1:} при равном бюджете LLM обучаемый маршрутизатор даёт более высокую точность. До доступа к числам зафиксированы: три бюджета LLM (25, 40, 50~\%); поправка Бонферрони ($\alpha/3 \approx 0{,}0167$); code-disjoint тестовая выборка $n = 1539$\footnote{Заранее зафиксированный снимок (\texttt{router\_train.parquet}, коммит \texttt{cd9ac7a}, 2026-05-13 02:11). Повторный запуск даёт $n = 1574$ ($\approx 2{,}3\,\%$ дрейф, не меняет вывод).}; опорная конфигурация --- статическое правило. Параметры зафиксированы в \texttt{src/eval/router\_pre\_registered.py}; коммит модуля сделан за 1~ч~11~мин до создания артефакта результатов, что обеспечивает временной приоритет процедуры над данными.

\paragraph*{Интерпретация и следствие для финальной конфигурации.}
Отклонение H1 воспроизводится на всех пяти моделях Слоя 4. Причина: основная вариация надёжности каскада сосредоточена на уровне атрибутов, а не товаров. Статическое per-(категория, атрибут) правило ловит именно эту неоднородность, маршрутизатор уровня ячейки дополнительной информации не приносит. Code-disjoint разбиение устраняет утечку бренда, которая объясняла ранние положительные результаты. Результат согласуется с RouterBench \cite{ref_12}. В финальной конфигурации применяется статическое правило --- прозрачное, поддающееся аудиту и не требующее переобучения; отклонение H1 --- один из трёх пунктов научной новизны (см. введение).

\subsubsection{Цикл <<аудит $\to$ правки $\to$ переобучение $\to$ измерение>>}

Замкнутый цикл итеративного улучшения каскада построен на сопоставлении собственных предсказаний с независимо проаудированной разметкой (LLM-аудитор \texttt{anthropic/claude-opus-4} слепо выносит суждения по каждой ячейке; измерение по неизменному списку ячеек исключает селекционный сдвиг). На pasta аудит 239 продуктов (1\,841 ячейка, 8 атрибутов; \texttt{cascade\_vs\_audited\_gold\_pasta.json}) выявил концентрацию ошибок на \texttt{pasta\_shape} (24,2~\% ячеек): функция \texttt{\_type\_b\_multiclass} обходила \texttt{categories\_tags} по порядку следования и отдавала приоритет обобщённому \texttt{en:noodles} над специфическими \texttt{en:tagliatelle}/\texttt{en:penne}/\texttt{en:fusilli}; ещё TYPE\_B не содержала legume-/filled-pasta. Точечные правки (коммиты \texttt{c1a0815}, \texttt{4bbd9e2}: обход по убыванию приоритета, пополнение TYPE\_B и regex многоязычными синонимами, 28 модульных тестов) при пересборке серебра подняли точность \texttt{pasta\_shape} с 27,6 до 59,6~\% ($+32{,}0$~п.~п.) при нулевом сдвиге шести нетронутых атрибутов; агрегированное серебро --- с 80,7 до 85,2~\%. Других изменений архитектуры не делалось — это подтверждает причинную связь правок и прироста.

\subsubsection{Симуляция активного обучения на 3-LLM consensus gold}
\label{sec:active_learning_sim}

Для оценки целесообразности активного обучения проведена симуляция на уже доступной разметке 3-LLM consensus gold (без дополнительной стоимости разметки человеком-аннотатором). Эталон разделён по товарным кодам в пропорции 70/30 (code-disjoint, seed 42); из пула отбираются две стратифицированные выборки одинакового размера $N \in \{50, 100, 200, 500\}$ --- \emph{active} (ячейки, на которых ML уверенно ошибается, margin-disagreement, $\ge P_{75}$) и \emph{random} (случайная выборка), после чего Слой 2 переобучается на \texttt{silver + N gold} с sample\_weight 5 и измеряется на отложенной выборке. По 24~циклам переобучения (3 категории $\times$ 4 значения $N$ $\times$ 2 стратегии) active-стратегия \emph{не} превзошла random ни на одной паре: при $N=500$ pasta active $-0{,}14$~п.п.\ против random $+0{,}28$~п.п.; chocolate active $+0{,}27$~п.п.\ против random $+0{,}96$~п.п.; cheeses active $-0{,}12$~п.п.\ против random $+1{,}74$~п.п. Объяснение --- ограниченный размер пула кандидатов активного обучения (26--79 <<уверенно-ошибочных>> ячеек на категорию): при $N \ge 100$ active фактически добавляет весь пул, тогда как random продолжает расти на пуле из 4\,461--5\,954 ячеек. Оговорка: симуляция $\neq$ настоящий AL с человеческой разметкой (\texttt{gold} здесь --- LLM-консенсус, а пул кандидатов сужен производственным каскадом). Подробное обсуждение полноценного AL-пилота с человеком-аннотатором --- в <<Перспективах развития темы>> Заключения. Артефакты --- \texttt{datasets/processed/active\_learning\_results.parquet}, \texttt{active\_learning\_summary.json}; ячейка \texttt{active-learning-curve} в \texttt{notebooks/03\_evaluate.ipynb}.

\subsubsection{Уточнение схемы атрибутов: независимые свойства}
\label{subsec:schema_refinement}

Анализ ошибок на LLM-consensus gold показал, что значение \texttt{filled} в исходной 5-классовой формулировке \texttt{chocolate\_type} \texttt{\{dark, milk, white, filled, other\}} работает как структурная характеристика товара (наличие начинки) и не зависит от типа какао-массы. Один шоколад одновременно может быть \texttt{dark} (по типу) и \texttt{filled} (по форме) --- Lindt-трюфели, Ritter Sport Marzapane, Ferrero Rocher. Объединение двух независимых свойств в один multiclass-атрибут давало macro-F1 0,50 при нулевом recall на \texttt{filled} и \texttt{other}. По принципу независимости в схему введён бинарный атрибут \texttt{chocolate.is\_filled}, не зависящий от \texttt{chocolate\_type} (3-class) и \texttt{chocolate\_extra} (5-class); после разделения macro-F1 составила 0,971 / 0,910 / 0,857 соответственно. Аналогичный принцип отказа от мёртвых классов (recall $<$ 0,20 при $n_{\text{train}} < 100$) применён к \texttt{chocolate\_type.other}, \texttt{chocolate\_extra.\{other, with\_alcohol, with\_coffee\}}, \texttt{cheeses.texture.other}; класс \texttt{semi\_soft} объединён с \texttt{soft}. Соответствие train$\leftrightarrow$eval$\leftrightarrow$production обеспечивается единым описанием (\texttt{exclude\_classes} в \texttt{CATEGORY\_CONFIG} и \texttt{SCHEMA\_EXCLUDE} в \texttt{src/eval/metric\_table.py}). Метки \texttt{is\_filled} выведены semi-supervised из старой схемы и regex-шаблона \texttt{FILLED\_CHOCOLATE\_REGEX} (мультиязычные триггеры \texttt{truffle}/\texttt{praline}/\texttt{fourré}/\texttt{gefüllt}/\texttt{ripieno}); 1481 позитивный пример на silver, негативы проверены 2-LLM-консенсусом (0 переопределений).

Основные результаты:

\begin{enumerate}[label=\arabic*)]
    \item Реализован пятислойный каскад (Слой 0 категорайзер, regex, ML XGBoost на SBERT, байесовский валидатор, запасной слой на большой языковой модели) с указанием слоя-источника на каждое предсказание; вердикт формируется как последовательное конъюнктивное условие на пороги слоёв.
    \item Развёрнута трёхкомпонентная демонстрационная система (Go-шлюз, Python/FastAPI ML-сервис, статический HTML/JS) со стабильным контрактом API и подтверждённой работоспособностью на трёх категориях.
    \item Сквозная точность (E2E) 93,0~\% на 16\,360 ячейках LLM-consensus gold (20 атрибутов, без пересечения товарных кодов (code-disjoint)) в конфигурации «каскад + gemini-flash» — на 9,2~п.~п. выше опорной all-sonnet (83,8~\%) при стоимости в 580 раз ниже (доминирование по Парето). Верхняя оценка только-каскадной точности — 95,5~\% (cascade-only micro-accuracy на тех же ячейках, macro-F1 0,890). Каскад покрывает 97,3~\% ячеек; на LLM приходится 4,1~\% сложных ячеек (снижение стоимости 95,9~\% по сравнению с «одна LLM на всё»). Консервативная нижняя оценка по human gold (n = 566 cascade-valid): E2E 86,7~\%, cascade-only 91,3~\% --- операционный циркулярный сдвиг 4,2~п.~п. (каскад) / 6,3~п.~п. (E2E). В сценарии с открытой моделью каскад + gpt-oss-120b достигает 90,6~\% — на 21,3~п.~п. выше одиночного вызова той же модели. Полная таблица — в 3.3.2.
    \item Поатрибутный разбор: Слой 2 — основной (71--90~\% покрытия, 93,5--98,6~\% точности); Слой 1 покрывает 18--23~\% на pasta/chocolate с точностью 87--100~\%; байесовский валидатор работает точечно (+38~п.~п. на chocolate/contains\_nuts); LLM добавляет +1,4--1,7~п.~п. при 4,1~\% обращений.
    \item Заранее объявленная H1 об обучаемом маршрутизаторе отклонена на трёх бюджетах после поправки Бонферрони; результат согласуется с RouterBench \cite{ref_12}.
    \item Цикл «аудит — правки — переобучение — измерение» воспроизведён 3/3: pasta +18,2~п.~п., chocolate +16,3~п.~п., cheeses +14,4~п.~п. на проблемных срезах.
    \item Зафиксированы три принципа проектирования схемы атрибутов (независимость, отказ от мёртвых классов, консервативная агрегация rule-based слоёв; 3.3.7.4). Выделение бинарного атрибута \texttt{chocolate.is\_filled} как структурного свойства, независимого от \texttt{chocolate\_type}, повысило macro-F1 \texttt{chocolate\_type} с 0,50 (5-class) до 0,973 (3-class) при macro-F1 \texttt{is\_filled} 0,861 на новой бинарной задаче. Удаление мёртвых классов (recall < 0,20, n\textsubscript{train} < 100) дополнительно повысило macro-F1 \texttt{chocolate\_extra} и \texttt{cheeses.texture}.
    \item Устойчивость по языкам (разброс 3~п.~п. на 5 языках) и сравнение с лексическим базисом (20 из 20 пар сопоставимо или выше, +25--30~п.~п. на нутриент-производных) подтверждены; поатрибутные решения \ref{subsec:schema_refinement} обеспечивают высокое покрытие ML-слоя при доле обращений к LLM 4,1~\%.
\end{enumerate}
