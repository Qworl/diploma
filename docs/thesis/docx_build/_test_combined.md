# Реферат

**Объём работы.** 114 страниц основной части, 4 главы, ≈18 рисунков, ≈21 таблица, 46 источников (10 российских и 36 зарубежных), 6 приложений.

**Ключевые слова.** ОБОГАЩЕНИЕ ТОВАРНЫХ ДАННЫХ, КАСКАДНАЯ АРХИТЕКТУРА, СЛАБЫЙ НАДЗОР, OPEN FOOD FACTS, БАЙЕСОВСКАЯ СЕТЬ, БОЛЬШАЯ ЯЗЫКОВАЯ МОДЕЛЬ, КАЛИБРОВКА, ИЗВЛЕЧЕНИЕ ПРИЗНАКОВ, ДОМИНИРОВАНИЕ ПО ПАРЕТО, АУДИТ-ЦИКЛ, ВЕКТОРНЫЕ ПРЕДСТАВЛЕНИЯ.

**Объект исследования.** Процесс автоматизированного обогащения товарных каталогов интернет-магазинов с использованием открытых источников данных.

**Предмет исследования.** Гибридная каскадная архитектура с ансамблевой оценкой уверенности классификаторов и адаптивным обращением к большой языковой модели как запасному слою.

**Цель работы.** Разработать гибридную каскадную систему автоматизированного обогащения товарных данных для интернет-магазина, обеспечивающую высокую точность извлечения категориальных атрибутов при сокращённой стоимости обращения к большой языковой модели и поддерживающую развёртывание на открытых моделях.

**Методы.** Многоязычные векторные представления текста на базе модели paraphrase-multilingual-MiniLM-L12-v2 (SBERT, поддержка 50+ языков), классификатор XGBoost с регуляризацией и поатрибутными порогами уверенности, байесовская сеть со структурой, найденной алгоритмом Hill Climb по критерию BIC (библиотека pgmpy), доверительные интервалы с кластеризацией по брендам через ресэмплированный бутстрэп, бакетирование числовых нутри-полей, согласие трёх независимых больших языковых моделей (Sonnet 4.5 + GPT-4o + Gemini 2.5 Flash) для построения эталонной разметки на текстово-семантических атрибутах, слепая верификация моделью Claude Opus 4, разбиение на обучающую и тестовую части без пересечения брендов, предзарегистрированная проверка гипотезы с поправкой Бонферрони на множественные сравнения.

**Результаты.** Реализована и эмпирически проверена гибридная каскадная архитектура из пяти слоёв (категорайзер Layer 0 — регулярные выражения — классификатор XGBoost на векторных представлениях SBERT — байесовский валидатор плотностей — запасной слой большой языковой модели) на трёх продуктовых категориях открытого каталога Open Food Facts (паста, шоколад, сыры). На тестовой выборке без пересечения брендов размером 4350 ячеек по 22 парам «категория-атрибут» итоговая конфигурация достигает 92,8 % сквозной точности при обращении к большой языковой модели на 3,3 % ячеек в режиме «каскад + gemini-flash»; при развёртывании на собственных мощностях с открытой моделью gpt-oss-120b — 92,3 % точности, что на 23,0 п. п. выше прямого использования gpt-oss-120b (69,3 %). Каскад без запасного слоя самостоятельно покрывает 96,7 % ячеек со средней точностью 90,5 %. Достигнуто доминирование по Парето разработанной системы над прямым использованием большой языковой модели по двум осям одновременно — точности и стоимости (+9,0 п. п. точности и сокращение стоимости в 720 раз относительно прямого использования Claude Sonnet 4.5). Предзарегистрированная гипотеза о превосходстве обучаемого стоимостно-чувствительного маршрутизатора над статическим правилом отклонена после поправки Бонферрони на трёх бюджетах. Реализован замкнутый цикл «аудит — правки экстрактора — переобучение — измерение» с кросс-доменной репликацией 3 из 3. Разработана демонстрационная система из трёх компонентов (шлюз API на Go, ML-сервис на Python/FastAPI, веб-интерфейс), реализующая стабильный контракт REST API.

**Использование результатов.** Разработанная архитектура применима в системах управления товарной информацией (PIM-системах) интернет-магазинов. Внедрение системы позволяет: повысить полноту автоматического заполнения карточек товаров до 92,8 %, сократить стоимость обработки в 720 раз по сравнению с прямым использованием Claude Sonnet 4.5, сократить ручную нагрузку оператора каталога в 10–20 раз за счёт перевода в режим выборочной верификации, обеспечить развёртывание на собственных мощностях без отправки партнёрских данных во внешние API больших языковых моделей.

# Определения, обозначения и сокращения

В настоящей выпускной квалификационной работе применяются следующие термины с соответствующими определениями.

**Серебряная разметка** (в литературе по слабому надзору также silver) — набор пар «товар — целевое значение атрибута», полученный автоматически из открытых источников данных (теги Open Food Facts) и используемый для обучения моделей. Серебряная разметка содержит шум и неполноту и противопоставляется эталонной разметке.

**Эталонная разметка** (в литературе также gold) — пары «товар — целевое значение», прошедшие верификацию (согласованным мнением нескольких языковых моделей и/или слепой разметкой более сильной языковой модели); используется как опорная истина при оценке каскада.

**Слабый надзор** — режим обучения с использованием неполной или зашумлённой разметки, формируемой автоматически из доступных источников вместо ручной разметки экспертом.

**Каскадная архитектура** — последовательность алгоритмических слоёв, каждый из которых обрабатывает только те объекты или атрибуты, которые не были закрыты предыдущими слоями с заданной уверенностью.

**Многоуровневая фильтрация по уверенности** — формализация поведения каскада как последовательного конъюнктивного условия на прохождение калиброванных порогов уверенности на каждом слое. Реализует требование утверждённой темы об «ансамблевой оценке уверенности моделей».

**Покрытие** — доля ячеек «товар, атрибут» в тестовой выборке, для которых каскад дал предсказание выше порога уверенности на слоях 1-3 (без обращения к запасному слою).

**Точность на покрытом срезе** — доля верных предсказаний среди тех ячеек, для которых каскад дал ответ без обращения к запасному слою.

**Сквозная точность** — точность системы на полной тестовой выборке, при которой отказы каскада засчитываются как неверные ответы (либо заменяются ответом запасного слоя при включённом Layer 4).

**Разбиение без пересечения брендов** — построение разбиения выборки на обучающую, валидационную и тестовую части, при котором один бренд попадает ровно в одну из трёх частей. Исключает утечку признака «бренд — атрибут» при оценке качества системы.

**Цикл «аудит — правки — переобучение — измерение»** — методологический приём улучшения системы, при котором обнаружение конкретных дефектов эталонной разметки через аудит приводит к правкам экстрактора, затем к переобучению моделей и измерению прироста точности на той же аудит-выборке.

**OFF** — Open Food Facts, открытый краудсорсинговый каталог продовольственных товаров под лицензией ODbL.

**SBERT** — Sentence-BERT, многоязычная модель векторного представления предложений (используется paraphrase-multilingual-MiniLM-L12-v2).

**XGBoost** — Extreme Gradient Boosting, библиотека градиентного бустинга деревьев решений.

**ECE** — Expected Calibration Error, ожидаемая ошибка калибровки вероятностей классификатора.

**CPD/DAG** — Conditional Probability Distribution / Directed Acyclic Graph, элементы байесовской сети.

**BIC** — Bayesian Information Criterion, критерий выбора структуры байесовской сети.

**PDO/AOP** — Protected Designation of Origin / Appellation d'Origine Protégée, защищённое наименование товара.
# Введение

## Актуальность темы исследования

Электронная коммерция сегодня устойчиво растёт: годовой объём российского сегмента в 2025 году составил 11,5 трлн руб. [1] на фоне продолжающегося роста мирового рынка электронной коммерции [2], а каталоги крупных интернет-магазинов исчисляются десятками миллионов товарных позиций (только индексируемая часть каталога Ozon в открытых аналитических базах превышает 38 млн позиций [3]), к которым ежедневно добавляются тысячи новых записей от партнёров-поставщиков. В этих условиях карточка товара становится центральным элементом цифровой витрины: от того, насколько она содержательно полна, зависят работа фасетного поиска, релевантность ранжирования и рекомендаций, корректность аналитики и в конечном счёте конверсия в покупки. При этом структура партнёрского ввода принципиально неоднородна — от одного наименования и бренда до расширенного набора полей с фотографиями и иноязычным составом. Образующиеся пробелы исторически закрывают контент-менеджеры вручную, проверяя и дополняя десятки целевых атрибутов на каждую карточку; при характерных масштабах каталога в миллионы позиций и тысячах новых записей в сутки такой подход не масштабируется ни по затратам, ни по доступности языковых компетенций [4].

Класс систем управления товарной информацией (Product Information Management) — Akeneo, Pimcore, Salsify и аналогичные — сложился из потребности хранить уже сформированную товарную информацию [5, 6, 7]. При этом задачу извлечения этой информации из неструктурированного партнёрского ввода такие системы систематически не решают: появляющиеся в них модули автоматического обогащения в большинстве случаев представляют собой обёртку над одной публичной большой языковой моделью, вызываемой напрямую на каждый товар (подробное сопоставление приведено в 1.2.3). Такой вызов экономически приемлем лишь для каталогов небольшого и среднего размера и не сопровождается гарантиями фактической корректности — особенно на числовых полях, в которых большие языковые модели систематически допускают фактические ошибки (3.3.2.5). Более того, рост ставок коммерческих API, ужесточение требований к локализации данных и отраслевой тренд на открытые модели в локальном развёртывании [8] дополнительно усиливают запрос на архитектурные решения, которые не сводятся к прямому вызову одной модели.

Из изложенного следует противоречие, которое и определяет актуальность работы. С одной стороны, автоматизация наполнения карточек — инженерная необходимость. С другой стороны, ни одна изолированная технология не покрывает все типы целевых атрибутов с приемлемой точностью и стоимостью одновременно: правила надёжны на числовых атрибутах, но мало покрывают семантически нагруженные поля; классические классификаторы требуют значительной размеченной выборки; большие языковые модели универсальны, однако дороги и подвержены фактическим ошибкам, особенно на числовых полях. В качестве разрешения этого противоречия в работе рассматривается гибридная каскадная архитектура — композиция последовательных слоёв, в которой каждый следующий слой подключается только к остатку, не закрытому предыдущими с заданной уверенностью. Такая композиция объединяет семантические возможности генеративных моделей с предсказательной силой классического машинного обучения и автоматической фильтрацией недостоверных значений. Это определяет актуальность работы как с научной стороны (систематическая проверка эффективности гибридного каскада), так и с практической (создание производственно-применимого комплекса с контролируемой стоимостью и возможностью локального развёртывания).

## Цель работы

Целью работы является разработка гибридной каскадной системы автоматизированного обогащения товарных данных интернет-магазина, которая обеспечивает высокую точность извлечения категориальных атрибутов при сокращённой стоимости обращения к большой языковой модели, поддерживает локальное развёртывание на открытых моделях и доминирует по Парето над прямым вызовом большой языковой модели одновременно по точности и стоимости.

## Задачи работы

Для достижения поставленной цели сформулированы и решены следующие пять задач:

1. разработать архитектуру гибридного каскадного конвейера обработки товарных данных с многоуровневой фильтрацией по уверенности и явным разделением слоёв — предкаскадный категорайзер, экстрактор регулярных выражений, классификатор машинного обучения на векторных представлениях, байесовский валидатор плотностей, запасной слой большой языковой модели; многоуровневая фильтрация формализует требование утверждённой темы об ансамблевой оценке уверенности моделей как последовательное конъюнктивное условие на калиброванные пороги слоёв;

2. реализовать каждый слой каскада в виде самостоятельного программного компонента — экстрактор регулярных выражений; классификатор машинного обучения, обучаемый на многоязычных векторных представлениях партнёр-доступных полей; байесовский валидатор, использующий обученную сеть атрибутов в роли фильтра статистически невероятных пар «бренд × значение»; запасной слой на основе большой языковой модели с поддержкой нескольких поставщиков, включая открытые модели для локального развёртывания;

3. построить эталонную разметку и проверочную выборку без пересечения брендов для оценки качества системы на трёх категориях товаров (паста, шоколад, сыры), сочетающую слабый надзор от тегов открытого каталога, поатрибутное согласие трёх независимых больших языковых моделей и слепую разметку референсной моделью, с разбиением на обучающую, валидационную и тестовую части без повторного появления одних и тех же брендов;

4. провести экспериментальную оценку разработанной системы — измерить точность сквозного прохождения каскада, поатрибутное покрытие и стоимость обработки на эталонной тестовой выборке; сопоставить полученные показатели с показателями прямого использования большой языковой модели; оценить вклад каждого слоя каскада, устойчивость к смещению по языкам входных данных и поведение байесовского валидатора как селективного сигнала на отбраковку фактических ошибок;

5. разработать демонстрационный программный комплекс, обеспечивающий взаимодействие конечного пользователя — оператора каталога — с каскадом через веб-интерфейс и стабильный программный интерфейс, и поддерживающий три производственных сценария развёртывания: с премиум-коммерческой большой языковой моделью, с бюджетной коммерческой языковой моделью и с открытой языковой моделью в локальном развёртывании.

Каждой задаче соответствует измеримый результат, который изложен в подразделе «Новизна и основные результаты».

## Объект и предмет исследования

**Объектом исследования** в настоящей работе является процесс автоматизированного обогащения товарных каталогов интернет-магазинов на основе открытых источников данных, при котором на входе имеется минимальный набор партнёр-доступных полей, а на выходе требуется получить структурированный набор целевых атрибутов.

**Предметом исследования** является гибридная каскадная архитектура обработки товарных данных с ансамблевой оценкой уверенности классификаторов и адаптивным селективным обращением к большой языковой модели в роли запасного слоя. Рассматриваются её точность, стоимостные характеристики, устойчивость к смещению входного распределения, а также вычислительные и эксплуатационные свойства, существенные для производственного применения.

## Теоретические и методические основы работы

Теоретическую основу работы составили классические результаты теории извлечения признаков из неструктурированного текста, статистического обучения и вероятностных графических моделей. Обучающая выборка строится методом слабого надзора (weak supervision) на тегах открытого каталога Open Food Facts; эталонная разметка для оценки качества формируется сочетанием детерминированных правил для нутриентно-производных атрибутов, регуляторных тегов и поатрибутного согласия трёх независимых больших языковых моделей со слепой проверкой референсной моделью (подробное описание процедуры — 3.2.3). Слой машинного обучения — это градиентный бустинг XGBoost поверх векторных представлений многоязычного дистиллированного энкодера SBERT (paraphrase-multilingual-MiniLM-L12-v2). Слой байесовского валидатора реализован библиотекой pgmpy, причём структура сети обучается алгоритмом Hill Climb по критерию BIC. Применимость изотонической пост-калибровки выходов классификатора исследована раздельно в 3.3.3.3 (фиксированная серебряная калибровка деградирует на эталонном срезе из-за дрейфа распределений; перекрёстная калибровка на распределении эталонной выборки снижает среднюю ECE с 0,070 до 0,043 — направление развития 5.5). Доверительные интервалы метрик качества получены процедурой кластерного бутстрэпа с ресэмплированием брендов; экспериментальный фрагмент организован по принципу предзарегистрированной проверки гипотез с поправкой Бонферрони на множественные сравнения.

Архитектурный подход к стоимостно-чувствительной композиции больших языковых моделей опирается на работы L. Chen и соавторов (FrugalGPT [9]), P. Aggarwal и соавторов (AutoMix [10]), D. Ding и соавторов (Hybrid LLM [11]), а также на бенчмарк Q. J. Hu и соавторов (RouterBench [12]). Методологическое оформление работы выполнено в соответствии с ГОСТ 7.32-2018, а библиографическое описание источников — с ГОСТ 7.1-2003.

**По задаче 3 (построение эталонной разметки)** — раздел 3.2 — построена многоисточниковая эталонная разметка для трёх категорий товаров на основе тегов открытого каталога, нутриентно-производных правил, поатрибутного согласия трёх независимых больших языковых моделей и слепой разметки референсной моделью; разбиение на обучающую, валидационную и тестовую части выполнено без пересечения брендов.

**По задаче 4 (экспериментальная оценка)** — разделы 3.3.2, 3.3.3, 3.3.4, 3.3.7 — получена сквозная точность 92,8 % на тестовой выборке без пересечения брендов из 4350 ячеек при 720-кратном сокращении стоимости относительно прямого вызова коммерческой референсной модели; доминирование каскада по Парето над прямым использованием большой языковой модели подтверждено на пяти моделях запасного слоя; вклад каждого слоя количественно охарактеризован, в том числе селективный вклад байесовского валидатора. Каскад без запасного слоя самостоятельно покрывает 96,7 % ячеек со средней точностью 90,5 %.

**По задаче 5 (разработка демонстрационного программного комплекса)** — разделы 4.1, 4.2 — реализована поддержка трёх производственных сценариев развёртывания (премиум-коммерческий, бюджетный коммерческий, локальный с открытой моделью) и трёх ролей пользователей: контент-менеджер, системный аналитик, инженер машинного обучения.

На основании совокупности полученных результатов сформулированы три пункта научной новизны.

**Первый пункт научной новизны.** Доказано доминирование разработанной гибридной каскадной системы по Парето над прямым использованием большой языковой модели на задаче обогащения товарных каталогов: на тестовой выборке без пересечения брендов размером 4350 ячеек одновременно достигаются превышение точности на 9,0 процентного пункта (92,8 % против 83,8 %) и сокращение стоимости обработки в 720 раз — без компромисса между точностью и стоимостью.

**Второй пункт научной новизны.** Эмпирически установлено, что в сценарии локального развёртывания каскадной системы с открытой большой языковой моделью (gpt-oss-120b) в роли запасного слоя каскад компенсирует ограниченные возможности малой открытой модели на сложных атрибутах за счёт специализированного слоя машинного обучения и обеспечивает прирост сквозной точности на 23,0 процентного пункта над прямым использованием той же открытой модели при тридцатикратном сокращении стоимости. Это позволяет говорить об архитектурной независимости решения от конкретного поставщика большой языковой модели.

**Третий пункт научной новизны.** Впервые на задаче обогащения товарных каталогов по предзарегистрированной процедуре с поправкой Бонферрони на множественные сравнения количественно установлено, что статическое per-(категория, атрибут) правило маршрутизации не уступает обучаемому стоимостно-чувствительному маршрутизатору по сквозной точности при равных бюджетах вызовов запасного слоя. Полученный результат уточняет применимость подхода обучаемой маршрутизации к рассматриваемому классу задач и согласуется с выводами бенчмарка RouterBench [12]. Кроме того, в работе разработан и кросс-доменно реплицирован замкнутый цикл «аудит эталонной разметки — корректировка экстрактора признаков — переобучение моделей — повторное измерение»: цикл воспроизведён на трёх категориях товаров из трёх с приростом сквозной точности на подвыборке аудированных проблемных ячеек +18,2, +16,3 и +14,4 процентного пункта для пасты, шоколада и сыров соответственно.

# Глава 1. Развёрнутая актуальность темы

Глава посвящена тому, чтобы обосновать тему работы, систематизировать уже существующие подходы к автоматическому обогащению товарных данных и сформулировать техническое задание на разрабатываемую систему.

## 1.1 Проблема обогащения товарных каталогов интернет-магазина

### 1.1.1 Электронная коммерция и роль товарных данных

Российский и мировой рынки электронной коммерции устойчиво растут: годовой оборот российского сегмента в 2025 году достиг 11,5 трлн руб. [1] на фоне продолжающегося роста мирового рынка [2]. Каталоги крупных площадок исчисляются десятками миллионов позиций (только индексируемая часть каталога Ozon в открытых аналитических базах превышает 38 млн позиций [3]), и ежедневно к ним добавляются тысячи новых артикулов товаров от партнёров-поставщиков. В таких условиях карточка товара становится центральным элементом цифровой витрины: от её структурированного набора атрибутов (тип, состав, габариты, маркировки качества, страна происхождения, предупреждения) зависит работа фасетного поиска, релевантность ранжирования и рекомендаций, точность аналитики и конверсия. Стоит отметить, что при неполном заполнении атрибутов цепочка «партнёрский фид — наполнение каталога — редакторский контроль — витрина» прерывается во втором звене: товар либо попадает на витрину в неполной форме — и тогда страдают поиск и конверсия, — либо задерживается до ручной доработки, отчего растут операционные затраты.

### 1.1.2 Неоднородность партнёрского ввода

Партнёрские данные принципиально неоднородны: для одного товара поставщик передаёт лишь наименование и бренд, для второго — расширенный набор полей с фотографиями, для третьего — состав произвольным текстом на иностранном языке, а для четвёртого присутствует только штрихкод. Заполненность нутри-полей упакованной пищевой продукции, как показывает анализ открытого каталога Open Food Facts [13], систематически ниже заполненности базовых полей наименования и бренда. Образующиеся пробелы исторически закрываются контент-менеджерами вручную, проверяя и дополняя десятки целевых атрибутов на каждую карточку, и при масштабах каталога в миллионы позиций и тысячах новых записей в сутки такой путь экономически неприемлем [4]. Более того, ручной труд плохо масштабируется по языкам: контент-команда, работающая с русскоязычным и англоязычным контентом, теряет качество, когда поступают описания на французском, немецком, итальянском или испанском. Особенно заметно это в категориях пищевой продукции, импортируемой из европейских стран.

### 1.1.3 Эффекты неполной карточки на пользовательский опыт

Неполная карточка оказывает три независимых воздействия на пользовательский опыт и экономику магазина. **Первое** — снижается качество фасетного поиска: если хотя бы один атрибут не заполнен, товар выпадает из релевантных подборок, когда покупатель применяет соответствующие фильтры (например, упаковка пасты без указания формы или типа зерна). **Второе** — растут возвраты и негативная обратная связь; это особенно критично для атрибутов с правовым или диетическим значением, таких как органическое происхождение, отсутствие глютена, аллергены, поскольку покупатель фиксирует расхождение между обещанием карточки и фактическим товаром. **Третье** — возникает нагрузка на инфраструктуру модерации: «брошенная» карточка либо удлиняет цикл выхода товара на витрину, либо становится источником повторных правок.

### 1.1.4 Существующие системы управления товарной информацией не решают задачу

Класс систем управления товарной информацией (Product Information Management, PIM-системы) — например, такие как Akeneo, Pimcore, Salsify, Riversand, inRiver — сложился из корпоративной потребности хранить, согласовывать и публиковать товарную информацию в едином каталоге [5, 6, 7]. Однако функциональность PIM-систем сосредоточена на управлении уже сформированной информацией, а не на её извлечении из неструктурированного партнёрского ввода. Появляющиеся модули автоматического обогащения в большинстве случаев представляют собой обёртку над одной публичной большой языковой моделью с прямым вызовом на каждый товар; это экономически приемлемо лишь для каталогов небольшого и среднего размера и не сопровождается гарантиями фактической корректности. Альтернативой могла бы выступать интеграция с агрегаторами готовых описаний товаров от вендоров — однако такие агрегаторы не решают задачу извлечения атрибутов из произвольного партнёрского описания, а их покрытие ограничено крупными брендами.

### 1.1.5 Противоречие и постановка задачи

Изложенное определяет противоречие, которое и лежит в основе актуальности работы. С одной стороны, автоматизация наполнения карточек — инженерная необходимость. С другой стороны, ни одна изолированная технология не покрывает все типы целевых атрибутов с приемлемой точностью и стоимостью одновременно: правила надёжны на числовых атрибутах, но дают низкое покрытие на семантически нагруженных полях; классические классификаторы требуют значительной размеченной выборки и плохо переносятся между языками входных данных; большие языковые модели универсальны, но дороги [9] и систематически допускают фактические ошибки на числовых полях, требующих агрегирования из текста (эмпирическая характеристика — 3.3.2.5). Из противоречия вытекает рабочая архитектурная гипотеза: каскадная композиция слоёв обработки, в которой каждый следующий слой подключается только к остатку, не закрытому предыдущими с заданной уверенностью, способна совместить преимущества отдельных технологий. Проверка этой гипотезы и составляет содержательное ядро работы.

## 1.2 Литературный обзор

В настоящем разделе систематизируется научный и индустриальный задел по трём направлениям, которые образуют теоретическую основу разрабатываемой системы: извлечение признаков из текстовых описаний товаров, стоимостно-чувствительные каскады больших языковых моделей и существующие промышленные системы управления товарной информацией.

### 1.2.1 Извлечение признаков из текстовых описаний товаров

В академической литературе задача восполнения пропущенных атрибутов в товарных каталогах рассматривается как частный случай задачи извлечения признаков из неструктурированного текста (information extraction, IE). Сложившиеся подходы делятся на три группы: формальные правила, классические статистические модели и нейросетевые модели на основе трансформеров. Стоит отметить, что эти группы не являются взаимоисключающими; именно их сочетание и образует основу для каскадных архитектур, которые рассматриваются ниже.

**Правила и регулярные выражения.** Формальные шаблоны надёжно извлекают атрибуты с устойчивой лексической разметкой, например, такие как процент жира, масса нетто, время приготовления, минимальный возраст; стоимость инференса при этом близка к нулю, а интерпретируемость обеспечивается по построению. Главное ограничение — низкое покрытие на атрибутах, которые требуют семантического понимания, таких как тип крупы, форма пасты, маркировка органического происхождения.

**Статистические модели над поверхностными признаками.** Классификаторы поверх TF-IDF-векторизации и градиентный бустинг деревьев решений (XGBoost [14], LightGBM [15]) хорошо работают при достаточной обучающей выборке и одноязычном входе; результаты применения методов машинного обучения к прогнозированию бизнес-решений и классификации в системах электронной коммерции приведены в работе Г. И. Афанасьева и соавторов [16]. Однако такие модели слабо переносятся на многоязычные тексты и не способны учитывать семантическое сходство.

**Векторные представления на основе трансформеров.** Архитектура трансформера [17] и модели семейства BERT [18] обеспечили новое качество в задачах извлечения текста. Sentence-BERT [19] и его многоязычные дистиллированные варианты [20] позволяют получать векторные представления предложений фиксированной размерности, поверх которых применяется произвольный классификатор; задачи автоматической категоризации и извлечения признаков из товарных каталогов рассмотрены в работе А. Г. Колонина [21], а систематическое изложение методов автоматической обработки естественного языка и извлечения информации дано в учебнике Е. И. Большаковой и соавторов [22].

**Специализированные системы извлечения атрибутов товаров.** В индустриальной литературе крупных торговых площадок выделяются три эталонные системы:

* TXtract [23] (Karamanolakis et al., ACL 2020, Amazon) — многозадачный нейронный кодировщик с условием на таксономию категорий, обеспечивающий извлечение атрибутов в крупных каталогах при значительном дисбалансе классов;
* MAVE [24] (Yang et al., WSDM 2022, Google) — многоисточниковый кодировщик на основе BERT с кросс-вниманием, использующий не только наименование, но и описание, спецификации и другие текстовые поля карточки;
* OpenTag [25] (Zheng et al., KDD 2018) — двунаправленная рекуррентная архитектура BiLSTM-CRF с механизмом внимания, формулирующая задачу извлечения атрибутов как задачу разметки последовательности.

Перечисленные системы демонстрируют качество извлечения отдельных атрибутов в диапазоне 85–92 % F1 на специализированных корпусах. При этом сопоставление этих подходов с каскадными архитектурами, привлекающими большую языковую модель в роли запасного слоя, в открытой литературе систематически не представлено: специализированные системы и каскады LLM рассматриваются как самостоятельные направления. Настоящая работа частично закрывает этот пробел.

### 1.2.2 Стоимостно-чувствительные каскады больших языковых моделей

С появлением спектра больших языковых моделей разной мощности и стоимости в литературе оформилась подобласть стоимостно-чувствительной маршрутизации (cost-aware LLM routing). Её задача — направлять каждый запрос к минимально достаточной модели так, чтобы не потерять качество относительно самой мощной модели.

**FrugalGPT.** Главный референс направления — работа L. Chen, M. Zaharia и J. Zou [9], в которой предложена каскадная композиция языковых моделей по возрастанию стоимости с прерыванием на первом достаточно уверенном ответе; каскад из трёх-четырёх моделей с откалиброванной уверенностью обеспечивает то же качество, что и прямой вызов самой дорогой модели, при стоимости на порядок ниже. Настоящая работа опирается на идеи FrugalGPT в части последовательного прерывания и калибровки уверенности.

**AutoMix.** Работа P. Aggarwal, A. Madaan и соавторов [10] основана на самопроверке ответа моделью меньшего размера: при сомнении модель сама делегирует запрос вышестоящей. Подход реализуется внутри пары «малая LLM — большая LLM», тогда как разрабатываемая система, наоборот, выносит роли валидатора и предсказателя в раздельные слои каскада.

**Hybrid LLM.** Работа D. Ding, A. Mallick и соавторов [11] рассматривает маршрутизацию между моделью на пограничном устройстве и облачной моделью; сценарий настоящей работы «on-premise gpt-oss-120b плюс коммерческое API как запасной слой» прямо соответствует этой постановке.

**RouterBench.** Бенчмарк Q. J. Hu, J. Bieker и соавторов [12] систематически измерил эффективность обучаемых маршрутизаторов между большими языковыми моделями и показал, что обучаемые маршрутизаторы не доминируют над простыми статическими политиками на значительной части задач при локализованной структуре ошибок. Этот вывод согласуется с результатом главы 3, где на задаче обогащения товарных каталогов впервые количественно установлено и проверено по предзарегистрированной процедуре, что статическое per-(категория, атрибут) правило не уступает обучаемому маршрутизатору по сквозной точности при равном бюджете вызовов запасного слоя.

### 1.2.3 Существующие промышленные PIM-системы и анализ аналогов

Чтобы позиционировать разработку относительно индустриальных аналогов, отобраны три коммерческие PIM-системы — Akeneo, Pimcore и Salsify — и построена сравнительная таблица по семи функциональным критериям, существенным для задачи автоматического обогащения каталога (таблица 1.1; источники — документация вендоров [5, 6, 7]).

**Таблица 1.1 — Сравнение существующих PIM-систем и разрабатываемой системы**

| № | Критерий | Akeneo | Pimcore | Salsify | Разрабатываемая система |
|---|---|---|---|---|---|
| 1 | Централизованное хранение каталога | да | да | да | не входит в задачу |
| 2 | Распределение по каналам сбыта | да | да | да | не входит в задачу |
| 3 | Автоматическое обогащение атрибутов | нет (только ручная редактура) | частично (правила обогащения) | нет (есть AI Suite как обёртка над сторонней LLM) | да (каскадная архитектура) |
| 4 | Извлечение признаков из неструктурированного текста | нет | нет | нет | да (слои ML и LLM) |
| 5 | Поддержка многоязычного входа | через ручные переводы | через ручные переводы | через ручные переводы | встроенная (многоязычные эмбеддинги, 50+ языков) |
| 6 | Открытый исходный код | community-редакция | да | нет | да (включая возможность on-premise развёртывания LLM) |
| 7 | Стоимостно-чувствительная обработка | нет | нет | нет | да (каскадная композиция с доминированием по Парето по стоимости и качеству) |

Из таблицы 1.1 следует, что коммерческие PIM-системы хорошо покрывают хранение, версионирование и распределение уже сформированной информации, однако систематически не решают задачи извлечения атрибутов из произвольного партнёрского текста, а появляющаяся функция автоматического обогащения реализуется как обёртка над сторонней языковой моделью. Таким образом, ни одно из проанализированных решений не закрывает совокупность критериев интернет-магазина одновременно — автоматическое обогащение, многоязычную обработку, контролируемую стоимость и возможность on-premise развёртывания, — и это обосновывает целесообразность разработки самостоятельной системы.

### 1.2.4 Слабый надзор, калибровка и сопутствующая методология

Принципиальная сложность построения систем автоматического обогащения состоит в том, что отсутствует достаточно большая ручная разметка целевых атрибутов; соответствующая постановка обозначается термином «слабый надзор» (weak supervision), методический инструментарий которого систематизирован в работе A. Ratner и соавторов «Snorkel» [26]. Пригодным источником слабого эталона для товарных каталогов выступает Open Food Facts [13] — открытая база более 4,5 млн записей о пищевых продуктах с пользовательскими тегами.

Чтобы каскад работал корректно, выходы классификаторов должны быть откалиброваны. Базовыми процедурами калибровки выступают масштабирование Платта [27] и изотоническая регрессия [28]; современный анализ калибровки глубоких моделей и поведения метрики Expected Calibration Error (ECE) приведён в работе C. Guo и соавторов [29]. Точность при ограниченной выборке оценивается кросс-валидацией и бутстрэпом [30], а интервальная оценка пропорций строится по формуле Вильсона [31]. В части аппарата байесовских сетей работа опирается на монографии J. Pearl [32], D. Heckerman et al. [33], А. Л. Тулупьева и соавторов [34] и библиотеку pgmpy [35]; для поиска структуры применяется алгоритм Hill Climb с критерием BIC [36]. Прикладные вопросы построения рыночно-ориентированных моделей машинного обучения и устойчивости к дрейфу данных в розничных каталогах рассмотрены А. А. Артемовым [37], а отраслевой контекст ограниченной масштабируемости стандартных подходов к управлению ассортиментом на маркетплейсах — С. А. Сергеевым [38]. Активное обучение и краудсорсинг как методы оптимизации разметки в условиях ограниченного бюджета систематизированы Р. А. Гилязевым и Д. Ю. Турдаковым [39], а ранние работы по семантическим пространствам знаний — В. Ф. Хорошевским [40].

## 1.3 Техническое задание на разрабатываемую систему

В настоящем разделе формулируется техническое задание на разрабатываемую систему. Оно подразделяется на функциональные требования (что система должна делать), нефункциональные (с какими характеристиками) и архитектурные (каким способом она организована).

### 1.3.1 Функциональные требования

**Ф-1. Принимаемый формат входных данных.** Система должна принимать на входе товар, описанный полями, доступными от партнёра-поставщика: наименование (`product_name`), бренд (`brands`), список ингредиентов в произвольной форме (`ingredients_text`), масса / объём / упаковка (`quantity`), идентификатор категории (`category`, опционально). Все поля, кроме наименования, считаются необязательными.

**Ф-2. Возврат заполненных значений целевых атрибутов.** Система должна возвращать для каждого целевого атрибута предсказанное значение, оценку уверенности и идентификатор слоя каскада, на котором было принято финальное решение. Тем самым обеспечивается отслеживаемость источника каждого предсказания и возможность ручной верификации контент-менеджером.

**Ф-3. Покрытие предметных категорий.** В пределах настоящей работы система поддерживает заполнение целевых атрибутов для трёх категорий пищевой продукции: паста, шоколад и шоколадные изделия, сыры. Выбор именно этих трёх категорий обоснован тем, что в Open Food Facts по ним имеется достаточный объём обучающих данных, доступен аудит-эталон с согласием трёх больших языковых моделей и слепой разметкой Opus, а сами категории репрезентативны с точки зрения распределения типов целевых атрибутов — числовых, бинарных, мультиклассовых семантических.

**Ф-4. Автоматическое определение категории.** Если категория явно не указана, система должна определять её автоматически — на основании поступившего текстового описания товара. Эта функция реализуется отдельным предкаскадным слоем (Layer 0).

**Ф-5. Запасной слой на основе большой языковой модели.** Если получить однозначный ответ на конкретный атрибут средствами слоёв 1–3 каскада не удаётся, система должна обращаться к большой языковой модели как к запасному слою. При этом запасной слой подключается селективно — только для тех атрибутов конкретного товара, по которым предыдущие слои не выдали уверенного ответа.

**Ф-6. Диагностический вывод.** Система должна возвращать диагностическую информацию: результат работы валидатора (понижение или подтверждение предсказания), агрегированные оценки уверенности по слоям и маршрут запроса по каскаду. Эта информация необходима для отладки, аудита и накопления данных о поведении системы в эксплуатации.

### 1.3.2 Нефункциональные требования

**НФ-1. Точность.** Целевая сквозная точность каскада на эталонной тестовой выборке без пересечения брендов между обучающей и тестовой частями — не менее 85 %; в конфигурации с коммерческой большой языковой моделью в запасном слое — не менее 90 %.

**НФ-2. Стоимость.** Стоимость обработки одного товара каскадом должна быть существенно ниже стоимости прямого вызова большой языковой модели на тот же товар. Целевой коэффициент снижения — не менее 2,5×; ограничение сверху не задаётся, фактически достижимое значение фиксируется по результатам эмпирической оценки в 3.3.2.

**НФ-3. Производительность.** Время отклика на один товар при работе без обращения к запасному слою — не более 500 мс на потребительском ноутбуке без специализированного ускорителя; при необходимости обращения к запасному слою — не более 5 секунд (определяется временем ответа внешнего API большой языковой модели).

**НФ-4. Многоязычность.** Система должна поддерживать обработку описаний товаров на пяти рабочих языках европейского рынка пищевой продукции: французском, английском, немецком, итальянском и испанском. Это соответствует наиболее представленным языкам в Open Food Facts и моделирует реалистичный многоязычный партнёрский поток.

**НФ-5. Возможность on-premise развёртывания.** Система должна поддерживать сценарий полностью локального развёртывания, при котором обращения к внешним коммерческим API исключаются. Этот сценарий реализуется через подключение в запасной слой открытой языковой модели (gpt-oss-120b) и предъявляет к каскаду требование вендорной независимости.

### 1.3.3 Архитектурные требования

**А-1. Каскадная архитектура с раздельными слоями.** Система реализует последовательность слоёв обработки по принципу «передачи остатка»: каждый последующий слой обрабатывает только те атрибуты, по которым предыдущие слои не выдали ответа с уверенностью выше калиброванного порога. При этом архитектурно слои разделены и могут обновляться независимо.

**А-2. Независимое обновление слоёв.** Изменение или переобучение любого отдельного слоя — обновление правил, дообучение классификаторов слоя 2, замена языковой модели в запасном слое — не должно требовать перезапуска или повторного развёртывания других слоёв, а также API-шлюза системы.

**А-3. Стабильный контракт API.** Внешний интерфейс системы — формат запроса, формат ответа, перечень полей — фиксируется на этапе разработки и не изменяется в течение производственного цикла. Тем самым система интегрируется с внешними каталогами и PIM-системами без многократного переписывания клиентского кода.

**А-4. Демонстрационный программный комплекс с веб-интерфейсом.** Система сопровождается демонстрационным комплексом, который состоит из трёх компонентов: API-шлюз на языке Go, ML-сервис на языке Python (FastAPI) и одностраничный веб-интерфейс. Демонстрация обеспечивает верификацию работоспособности и наглядно представляет результаты работы каскада для контент-менеджера.

### 1.3.4 Соотношение технического задания и решаемых задач работы

Сформулированные требования полностью покрываются теми задачами, которые поставлены во введении (таблица 1.2).

**Таблица 1.2 — Соответствие требований технического задания и задач работы**

| № задачи | Краткая формулировка задачи | Покрываемые требования ТЗ |
|---|---|---|
| 1 | Разработать архитектуру гибридного каскадного конвейера | Ф-1, Ф-2, Ф-4, Ф-5, А-1 |
| 2 | Реализовать каждый слой каскада как самостоятельный программный компонент | Ф-6, А-2, А-3 |
| 3 | Построить эталонную разметку и проверочную выборку без пересечения брендов | Ф-3 (в части обеспечения данных для оценки на трёх категориях) |
| 4 | Провести экспериментальную оценку точности, покрытия и стоимости | НФ-1, НФ-2, НФ-3, НФ-4, НФ-5 |

## 1.4 Выводы по главе 1

В главе проведён анализ предметной области, систематизировано состояние литературы и обосновано техническое задание. По результатам анализа можно сформулировать следующие выводы.

1. **Проблема автоматического обогащения остаётся открытой.** Промышленные PIM-системы, такие как Akeneo [5], Pimcore [6], Salsify [7], ориентированы на хранение и распределение уже сформированной информации, а появляющиеся модули автоматического обогащения реализуются как обёртки над одной коммерческой большой языковой моделью и не отвечают требованиям стоимостно-чувствительной обработки больших каталогов.

2. **Научные подходы делятся на две группы, и ни одна из них не покрывает задачу полностью.** Специализированные системы извлечения атрибутов, такие как TXtract [23], MAVE [24], OpenTag [25], решают задачу с высоким качеством, однако требуют значительной размеченной выборки и не учитывают экономики обращения к моделям. Стоимостно-чувствительные каскады больших языковых моделей — FrugalGPT, AutoMix, Hybrid LLM — дают инструменты управления стоимостью, систематически сопоставленные в бенчмарке RouterBench; однако эти каскады рассматривают композицию из однородных моделей и не интегрируют классическое машинное обучение.

3. **Разрабатываемая система объединяет оба подхода в гибридный каскад**, который сочетает специализированные слои извлечения признаков — правила, машинное обучение на многоязычных эмбеддингах, байесовский валидатор — и стоимостно-чувствительный запасной слой LLM. Совокупность шести функциональных, пяти нефункциональных и четырёх архитектурных требований ТЗ формирует обязательство, выполнение которого верифицируется в экспериментальной части работы.

### 2.2.2 Почему каскад, а не сквозное решение

Альтернативой каскаду служат две крайние конфигурации: «всё через большую языковую модель» (all-LLM) и «всё через один классификатор» (all-ML). Обе рассмотрены в работе как точки отсчёта, и обе отвергнуты.

**Сквозное решение на LLM** даёт точность 83–94 % на различных моделях (3.3.2). Однако его стоимость линейно растёт с числом ячеек, ведь каждая ячейка — это отдельный платный вызов. Каскад же экономит порядка двух порядков стоимости при равной или большей точности, и достигается это за счёт стратифицированного решения: дешёвые детерминированные слои закрывают типовые случаи, а дорогая модель работает только на трудном остатке. **Сквозное решение на классическом ML** не подходит по принципиальной причине. Ряд целевых атрибутов является производным и требует знаний за пределами товарного описания — например, классификация по диетическим свойствам опирается на состав в сочетании с нормативными правилами. Для таких атрибутов, а также для холодного старта новых категорий необходим запасной слой LLM. Таким образом, каскад занимает нишу между двумя крайностями.

### 2.2.3 Почему SBERT, а не BERT или RoBERTa

В качестве кодировщика текстовых полей выбрана модель `paraphrase-multilingual-MiniLM-L12-v2` (SBERT [20]), и сделано это по трём соображениям. Во-первых, **многоязычность достаётся «бесплатно»**: SBERT поддерживает свыше 50 языков в едином векторном пространстве без дообучения, благодаря чему каскад легко переносится на новые рынки. Во-вторых, **представление компактно**: вектор размерности 384 в два раза меньше представлений полноразмерных BERT (768) и в 2,7 раза меньше представлений RoBERTa-large (1024); при этом, по результатам публикации многоязычных дистиллированных вариантов [20], качество семантической классификации сохраняется, а расходы памяти и времени вывода падают пропорционально. В-третьих, **модель готова к работе без доменной адаптации**: она обучалась на задаче парафразирования с контрастивным сигналом, и поэтому её представление хорошо подходит для классификации по семантической близости — дорогое доменное предобучение здесь не требуется.

### 2.2.4 Почему XGBoost, а не нейронная сеть

В качестве классификатора Layer 2 для каждого атрибута используется градиентный бустинг XGBoost [14] с регуляризацией (`subsample=0.8`, `colsample=0.8`, ранняя остановка, `gamma=0.1`). На первый взгляд более очевидным выглядел бы выбор нейросетевой головы, однако предпочтение отдано XGBoost, и тому есть несколько причин. Градиентный бустинг устойчиво работает на плотных векторных признаках при ограниченном объёме эталонной разметки (n ≈ 1 250 на категорию, см. 3.2.1), допускает пост-калибровку изотонической регрессией [28] и выполняет inference на CPU за единицы миллисекунд без графического ускорителя. Более того, поатрибутная архитектура «по одному классификатору на атрибут» упрощает цикл «аудит — правка — переобучение — измерение» (3.3.6).

### 2.2.5 Почему байесовская сеть и почему именно pgmpy

Чтобы реализовать валидатор плотностей и закрыть пункт темы о «скрытых статистических закономерностях каталога», выбрана дискретная байесовская сеть в реализации библиотеки `pgmpy` [35] версии 1.1.2. По сравнению с альтернативами — марковскими случайными полями и нейросетевыми автоэнкодерами — байесовская сеть допускает структурное обучение из данных (Hill Climb + BIC [36]) с интерпретируемым ориентированным графом атрибутов, обеспечивает дешёвый вывод по запросу через алгоритм Variable Elimination и явно выражает условные зависимости между атрибутами товара в форме набора локальных распределений. Выбор именно `pgmpy` обусловлен совместимостью с экосистемой Python и тем, что библиотека поддерживает как обучение структуры, так и параметрическую оценку распределений через `BayesianEstimator`.

### 2.2.6 Почему шлюз API на языке Go, а не моноязычный Python

Демонстрационная система реализована как два сервиса — шлюз на Go (`:8080`) и ML-сервис на Python/FastAPI (`:8001`), — соединённых внутренним HTTP-вызовом. Шлюз отвечает за сетевой ввод-вывод, валидацию JSON, CORS, логирование и отдачу статического фронтенда; для этой роли подходит Go, поскольку он даёт низкое потребление памяти, быстрый запуск и нативную поддержку конкурентного ввода-вывода. ML-сервис, в свою очередь, отвечает за модели и inference, а здесь Python-экосистема (PyTorch, sentence-transformers, XGBoost, pgmpy) не имеет полноценных аналогов. Такое разделение зон ответственности соответствует типовой production-архитектуре и позволяет масштабировать каждый компонент независимо.

### 2.2.7 Почему открытая большая языковая модель в качестве запасного слоя

В роли Layer 4 поддерживается набор взаимозаменяемых моделей, доступных через единый API OpenRouter: коммерческие Claude Sonnet 4.5, GPT-4o, Gemini 2.5 Flash, открытая gpt-oss-120b и открытая малая llama-3.2-3b. Все они функционально эквивалентны и различаются точностью, латентностью и стоимостью; в 3.3.2 они сопоставлены количественно. Многомодельная конфигурация с возможностью использовать открытую модель обоснована тремя соображениями. Во-первых, открытую gpt-oss-120b можно запустить в инфраструктуре заказчика, и тогда партнёрские данные вообще не передаются во внешние сервисы. Во-вторых, коммерческие LLM в роли Layer 4 взаимозаменяемы, что снижает стратегическую зависимость от конкретного провайдера. В-третьих, каскад компенсирует слабость малой открытой модели: при самостоятельном применении gpt-oss-120b проигрывает Claude Sonnet 14–15 п. п., однако в составе каскада, где запасной слой обрабатывает лишь ≈3 % ячеек, итоговая точность каскада с gpt-oss-120b превышает безусловное обращение к этой модели на 23,0 п. п. (3.3.2).
